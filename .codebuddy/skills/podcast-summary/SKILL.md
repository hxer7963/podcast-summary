# podcast-summary

把完整文稿重构为一篇可独立阅读的中文深度纪要。目标不是单纯缩短内容，而是同时做到：

- **覆盖充分**：重要访谈弧线、事实、故事、转折和边界不因压缩而消失。
- **有访谈感**：读者能看见问题怎样被提出、回答怎样转向、判断怎样形成。
- **有烟火气**：保留现场、亲历故事、个人承认、决策瞬间和能体现人物的细节。
- **有底层思考**：解释机制、前提、矛盾与二阶影响，但不让编辑推演淹没原始访谈。
- **结构清楚**：高密度结论在前，详尽叙事居中，逐章回望与升华收束。

> 播客与文章统一契约：完整读取 `transcript.md` + `README.md`，输出 `{basename}.md`。不得只依据标题、show notes、开头、搜索命中片段或既有 summary 生成全文。

## 输入 → 输出

- **输入**：`<episode_dir>/` 或 `<article_dir>/`，含 `transcript.md` + `README.md`
- **输出**：`<episode_dir>/{basename}.md`
- `basename` 是读完全文后提炼的核心论点或张力，不直接复用目录名。
- 文件名不超过 20 个中文字，只使用中英文、数字和连字符 `-`；不使用 `summary.md`、`research.md`，也不包含播客节目名。
- 文章场景下 `transcript.md` 可以是 `article.md` 的镜像，输出规则相同。

## 写作前置流程：先覆盖，再压缩

### 0.1 完整读取与累计理解

1. 先读 `README.md`，确认节目、链接、嘉宾、主持、时长和发布日期。
2. 从头到尾读取 `transcript.md`。长文稿可以分块，但每块只做内部笔记；最后一块读完前不得写成稿。
3. 累计记录后文对前文的补充、修正和反转。不要把嘉宾早期试探性回答误写成最终立场。
4. 识别 ASR 不确定项。无法确认的人名、数字或术语使用稳妥表述，不得擅自补全。
5. 访谈结尾、快问快答和个人问题也要读取。它们经常包含治理反思、人物评价、失败承认和最有温度的细节，不能因"不像主线"而自动丢弃。
6. README 若包含 timestamps 或章节清单，把每个非广告条目作为第二套目录逐项加入覆盖账本。除纯重复外，不得直接省略。
7. 单独复查 transcript 最后 20%。其中每个非重复实质话题必须进入账本；若含治理反思、失败承认、人物评价或个人结尾，详尽内容至少保留一项判断材料和一项人物材料。

### 0.2 建立话题覆盖账本（内部过程，不写入成稿）

按访谈推进顺序记录每一次实质性话题变化。每一项至少包含：

| 字段 | 要回答的问题 |
|---|---|
| 话题与位置 | 这段在文稿哪里，谈的核心问题是什么？ |
| 提问动机 | 主持人为什么在此处追问，它承接了什么前文或外部争议？ |
| 回答与转折 | 嘉宾先怎么答，追问后是否修正、承认边界或转向？ |
| 具体证据 | 有哪些数字、案例、原话、场景或亲历故事？ |
| 逻辑价值 | 它支撑、限制或反驳了哪个核心判断？ |
| 人物价值 | 它是否暴露判断方式、情绪、代价、关系或价值排序？ |
| 处理决定 | **展开 / 压缩 / 省略**，以及理由 |

处理规则：

- **展开**：改变核心判断，提供稀缺证据，形成重要转折，揭示真实矛盾，或显著刻画人物。
- **压缩**：只适用于与某个"展开"项实质重复的材料；必须记录它合并到哪个展开项、哪一章。独立的新问题、新回答、人物故事不能只因"不是商业主线"而压缩。
- **省略**：只限广告、寒暄、纯重复、无法辨认的 ASR 噪音或与主题完全无关的枝节；必须有明确理由。
- 亲历故事、现场尺度、失败承认、反常识细节、主持人有效反驳、嘉宾没有正面回答的问题，默认不得省略。
- 全部"展开"项必须分配到某个详尽章节，并至少获得一个完整自然段；存在有效追问时，该段还必须保留提问动机、回答转折和至少一项具体证据，不能用一句话点名交差。
- 全部"压缩"项必须能在成稿中定位到承接它的具体句子。完成映射前不得开始写作。

### 0.3 建立论证地图（内部过程，不写入成稿）

对主线使用以下链路：

```text
核心问题 → 嘉宾判断 → 成立前提 → 证据/故事 → 主持人追问或反例
→ 嘉宾的限定/转折 → 底层机制 → 直接结果 → 二阶影响 → 可观察信号
```

同时检查跨章节关系：

- 哪些观点互为前提，哪些只是表面并列？
- 嘉宾前后是否使用了不同时间尺度或目标函数？
- 哪些表面矛盾可以由边界条件解释，哪些矛盾必须保留？
- 哪些结论来自嘉宾，哪些是编辑把多段材料连起来后的推论？

### 0.4 区分事实层级

- **文稿事实**：文稿明确出现的主张、数字、案例和经历；准确归属说话人。
- **编辑推论**：由多处文稿证据推出的解释；用"这意味着""更深一层看"等措辞标明。
- **外部背景**：只补充理解当前论证必需且有把握的背景。实时事实、争议数字或无法核验的信息不引入。

严禁制造引语、补写嘉宾未表达的动机、把预测写成事实，或把"没有谈到"自动解释为刻意回避。

### 0.5 先设计章节，再检查覆盖

章节数量由内容密度决定，时长只是辅助：

- 短内容或单主题文章：通常 3-6 个章节。
- 20-45 分钟访谈：通常 5-9 个章节。
- 45 分钟以上且话题丰富的访谈：通常 **6-12 个**章节。

不要为了"主题化"把十个有独立问题、证据和转折的访谈弧线硬压成三四章。也不要按时间戳机械切片；应让每章既保留对话推进，又围绕一个清楚的命题或张力。

单章通常最多合并 2-3 个独立"展开"弧线。若展开项超过 18 个，允许超过 12 章；章节上限绝不能成为删除来源材料的理由。

列出章节蓝图后，将话题覆盖账本和 README timestamps 双向勾回。若一个"展开"项或非广告 timestamp 无章节归属，说明蓝图不完整。

## 成稿顺序与输出顺序

为避免弱模型把主要篇幅花在开头摘要上，**内部起草顺序**必须是：

1. Header
2. **先写 `## 详尽内容`**
3. 根据详尽内容提炼 `## 核心结论`
4. 根据跨章节证据提炼 `## 隐含推理与未明说暗示`
5. 最后压缩 `## TL;DR`
6. 写 `## 总结升华`、各章一句话回望和最终收束

最终文件仍按以下倒金字塔顺序排列：

```text
Header
## TL;DR
## 核心结论
## 隐含推理与未明说暗示
## 详尽内容
## 总结升华
```

全文只有以上五个必需二级标题。必要术语在第一次出现时用括号、同位语或短从句行内解释；**不再创建独立的术语/黑话章节**。

## 完整结构

### 1. Header

```markdown
# Episode Title

> 播客：**播客全称**
> 链接：https://...
> 嘉宾：Guest Names
> 主持：Host Names
> 时长：HH:MM:SS
> 发布日期：YYYY-MM-DD
```

- 第 6 行必须是发布日期，不得替换成转录引擎、segments 或 speakers 信息。
- 元数据以 README 为准；缺失项写"未知"，不猜测。
- 文章场景将"播客"改为文章来源，将"嘉宾"改为作者；确无主持时可省略主持行。

### 2. TL;DR

使用 `## TL;DR`。写成 1-2 个紧凑自然段，不使用 bullet，回答：

1. 谁在回答什么关键问题？
2. 最重要、最可争辩的 1-2 个判断是什么？
3. 判断成立依赖什么机制、前提或取舍？
4. 本期最稀缺的证据、故事或张力是什么？

TL;DR 是全文的认知地图，不是"本期讨论了 A、B、C"的目录，也不能替代正文。

### 3. 核心结论

使用 `## 核心结论`。提炼 5-10 条真正支撑全篇的判断，按重要性排序。每条包含：

- 可被反驳的结论；
- 至少一层因果机制；
- 文稿中的证据、案例或适用边界；
- 观点归属：嘉宾原意、多人共识或编辑综合。

不要把同一观点拆成多条凑数量，也不要用"AI 很重要""行业正在变化"之类正确废话。

### 4. 隐含推理与未明说暗示

使用 `## 隐含推理与未明说暗示`。提炼 4-8 条有证据的高置信度推论，优先寻找：

- 分散事实之间的跨段连接；
- 结论成立但没有明说的关键前提；
- 愿景与执行、增长与约束、安全与权力之间的取舍；
- 主持人问题没有被完整回答的论证缺口；
- 不同观点背后的时间尺度、目标函数或风险偏好差异；
- 人物经历和所处位置如何影响其判断。

推荐采用"**推论—依据—边界**"结构。编辑推论不能伪装成嘉宾原话，证据不足时写成待验证假设。

### 5. 详尽内容

使用 `## 详尽内容`。这是文章主体，也是质量差异最大的部分。

#### 5.1 信息预算

- 对有多个话题的访谈，详尽内容原则上应占正文（不含 Header）的 **55% 以上**。这是防止"前面结论很长、正文只剩提纲"的最低警戒线，不是鼓励注水。
- `核心结论`和`隐含推理`只能压缩已经在正文讲清的材料，不能独占重要故事或证据。
- 章节数量和篇幅随信息密度变化。每章通常 2-6 个自然段；复杂主线可以更长，辅助章节可以较短，但不能只有一句提纲。
- 删除重复、套话和空泛升华；增加篇幅必须来自来源覆盖、具体证据、对话转折或必要机制。

#### 5.2 单章叙事骨架

每章不需要机械加小标签，但要尽量形成以下推进：

```text
主持人为什么问 / 这个问题从哪里来
→ 嘉宾第一层回答
→ 追问、反驳、犹豫或话题转折
→ 数字、案例、现场、亲历故事或独特措辞
→ 这段回答背后的机制
→ 没回答完的部分、成立边界或代价
→ 回扣该章命题并自然带到下一章
```

关键要求：

- 先把嘉宾怎么说、为什么这样说讲清楚，再做编辑分析。单章中的编辑推演通常不超过约三分之一。
- 每个详尽章节至少有 2 项文稿证据；本章覆盖人物或亲历弧线时，至少 1 项必须是原始具体细节。
- 主持人的有效追问不是过场。它若改变回答、逼出前提或暴露缺口，必须写入。
- 直接引语只保留表达方式本身有价值且能够确认的短句；其余准确转述，不制造金句。
- 术语在首次出现时行内解释，让解释服务于故事，不另开词典。

#### 5.3 "烟火气"来自事实，不来自文学加工

优先保留以下材料：

- 嘉宾亲眼见到的场景、数量级和环境细节；
- 某次失败、争执、临时决定或偶然发现；
- "我不知道""我错了""我累了"等真实承认及其上下文；
- 关于同事、家庭、导师、用户或具体人物的片段；
- 能体现决策代价、性格、价值排序和认知更新的细节；
- 主持人与嘉宾之间有来有回的瞬间。

禁止为了"更生动"虚构动作、表情、心理活动和现场氛围。烟火气必须来自 transcript。

#### 5.4 逻辑与推演工具

按材料需要选择，不机械打卡：

- 因果机制与中间环节；
- 激励、资源和物理约束；
- 单位经济、规模效应和反馈回路；
- 反事实与成立边界；
- 竞争者、客户、供应商和监管者的反应；
- 短期、中期、长期的时间尺度；
- 二阶影响和瓶颈迁移；
- 支持或推翻判断的可观察信号。

数据必须说明口径、对比基准和"所以呢"。类比只能帮助建立直觉，不能替代证据。

#### 5.5 章节组织

- 标题表达问题、判断或张力，如"需求无上限，带着两个前提"，不用"行业背景""第一部分"等空标题。
- 同一话题散落多处时可以合并，但必须保留其中的问答顺序、关键转折和差异。
- 章节之间通过因果、转折或共同上层问题连接，不为追求"深度"强行合并彼此独立的访谈弧线。
- 允许沿访谈推进自然展开；"不按时间线机械切片"不等于删除访谈的对话逻辑。

### 6. 总结升华

使用 `## 总结升华`。它由三部分组成：

#### 6.1 底层机制与可迁移判断

用 3-5 个自然段提炼正文之上的高阶连接：

- 哪个底层机制同时解释了多个章节？
- 嘉宾同时持有哪些表面矛盾、实际带条件的判断？
- 哪个前提一旦失效，整套乐观或悲观叙事就会改变？
- 读者面对相似问题时应该观察什么变量，而不是照抄本期答案？

升华必须回到正文证据，包含至少一个边界或可观察信号。不要机械添加"人才、资本、愿景、世界观、人类文明"。

#### 6.2 各章一句话回望

使用三级标题 `### 各章一句话回望`。按照详尽内容的章节顺序，**每章恰好一句话**：

```markdown
- **一、章节名**：一句话说明该章回答了什么，以及它怎样推进全文主线。
- **二、章节名**：……
```

回望不是复制章节标题，也不是重新列一遍事实；它要让读者在一分钟内看见整场访谈的推进和整体感。回望条目数必须与详尽内容章节数一致。

#### 6.3 最后的收束

在回望之后用一个克制的自然段结束全文：合拢最重要的张力，指出最值得保留的问题或判断，不喊口号，不伪造确定性。

## 质量闸门

### 完整性

- [ ] 已完整读取 README 和 transcript，包括后半段、结尾与快问快答。
- [ ] README 中每个非广告 timestamp 都已进入账本，并可定位到详尽内容或一个有明确目标的重复合并项。
- [ ] 话题覆盖账本中的每个"展开"项都能在详尽内容定位到完整自然段，每个"压缩"项都能定位到承接句和目标章节。
- [ ] 没有为了压缩章节数丢掉独立的重要问题、故事、反驳、失败承认或人物片段。
- [ ] 对长且丰富的访谈使用了与内容匹配的 6-12 个章节，而非默认压成 3-6 章。
- [ ] transcript 最后 20% 的实质话题已覆盖；存在治理/失败/人物结尾时，至少保留了一项判断材料和一项人物材料。

### 结构与篇幅

- [ ] 最终文件严格包含 `## TL;DR`、`## 核心结论`、`## 隐含推理与未明说暗示`、`## 详尽内容`、`## 总结升华` 五个二级标题。
- [ ] 没有独立的术语/黑话章节；必要术语已在首次出现时行内解释。
- [ ] 对多话题访谈，详尽内容占正文至少约 55%；不足时先检查遗漏，不用套话补长度。
- [ ] 各章一句话回望的数量、顺序和标题与详尽内容完全一致。

### 访谈感与人物

- [ ] 重要章节交代了主持人为什么问、嘉宾如何答、追问带来了什么变化。
- [ ] 来源存在现场、亲历故事、个人承认或人物细节时，正文确实保留，而非只剩抽象商业结论。
- [ ] 烟火气全部来自文稿，没有虚构动作、心理和氛围。
- [ ] 嘉宾声音与编辑推论清楚分开，编辑分析没有压过原始访谈。

### 事实与论证

- [ ] 人名、数字、时间、案例和观点归属已回看文稿；不确定信息未擅自补全。
- [ ] 核心结论都有机制、证据或边界，不是话题清单。
- [ ] 隐含推理采用"推论—依据—边界"，没有内幕臆测和心理揣测。
- [ ] 关键因果链没有跳步，重要数据说明了基准与含义。
- [ ] 无法化解的矛盾被保留，预测没有写成事实。

### 编辑质量

- [ ] 详尽内容是连贯 prose，不是 bullet 提纲或每章一小段的压缩稿。
- [ ] 每段都在增加事实、故事、对话推进、解释或边界，没有靠重复制造长文感。
